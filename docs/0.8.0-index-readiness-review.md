# 0.8.0 检索产物结构独立审查

> 审查对象：Code2KB Spec 公开仓库中的发布样本、模板、检索构建器与消费契约。审查只读，未检查使用方知识库，也未运行生产 FTS、向量库或最终问答模型。以下为可复现的索引结构风险，不是线上错误回答统计。

## 能力现状

基础发布生成业务版、研发版、目录、功能大纲、检索索引、版本清单与指针。`发布/检索版`、检索清单、路由 JSON、离线评测和当前检索指针是显式启用的扩展，默认发布不会生成。检索单元含 `module_id`、`audience`、`release_id`、出处和摘要清单；业务消费只读业务单元。`retrieval-query` 返回候选证据，`answerability: not_assessed`，不能据词法命中率推断模型最终回答质量。

`render-facts` 当前输出供维护者使用的 JSON 片段（`validation/knowledge.py:1377–1387`），发布构建器并不自动使用这些片段。Starlette 检索夹具是人工根据公开证据撰写，不能证明生成器保留了相同边界。以下源码行号以 v0.7.0 审查基线为准。

## 发现与优先级

| 优先级 | 可复现证据 | 对索引与问答的影响 | 0.8 最小处置 |
| --- | --- | --- | --- |
| P1：限定与答案可能分离 | [`sections()`](../validation/retrieval_build.py)（第 72–94 行）按二级标题及问句式三级标题切分；[业务流程模板](../templates/业务流程.md)将适用条件、主流程、分支与回答边界设为相邻二级节。独立复现中，“仅限已登录用户”“返回当前用户订单”“跨租户访问未验证”被切为三个单元。 | FTS/向量检索可能只召回答案单元，有限 `top-k` 不保证同时带上条件和未知。模型可从其他正文补足，故尚非已证实错误回答。 | 回答单元保留决定结果的父条件、例外和未知；无法安全合并时报警并进入审核。 |
| P2：主题缺少可读上下文 | [公开旧样本](../conformance/legacy-release/发布/业务版/订单/订单查询/模块概览.md)的“订单查询：模块概览 / 说明”经同一规则得到主题“说明”；`question_variants()`只是去掉问句前缀。 | 字段式 FTS、向量正文和展示层若只用主题，缺少模块名和父主题。出处路径仍含模块信息，故并未完全丢失上下文。 | 单元保留可读模块名及标题路径；泛标题补上下文；标题别名不宣传为真实问法扩展。 |
| P2：术语表未进入可选检索扩展 | [元数据协议](../spec/03-元数据协议.md)允许业务术语表，[基础检索索引生成器](../validation/governance.py)会链接它；检索构建器 `SOURCE_ORDER` 没有它。根级术语表还允许没有 `module_id`。 | 仅导入检索扩展的消费者可能漏掉缩写、同义词和独立定义；基础发布仍包含术语表。 | 本版以独立覆盖报告列出遗漏内容、原因和原文位置；全局术语身份后续设计。 |
| P2：内部锚点未重定向 | [`rewrite_links()`](../validation/retrieval_build.py)（第 106–117 行）直接保留 `#…`。有效输入 `[见条件](#适用条件)` 在拆分后仍指向新单元内部，而目标可能只在原文。 | 循链接补条件时可能无法到达。该问题由构造输入复现，尚未在已提交公开样本中发现同例。 | 将跨节内部锚点指回已发布原文，或可靠定位目标单元。 |
| 集成契约：外部索引替换未定义 | 检索清单有 `unit_id`、路径和摘要；`unit_id` 依赖来源文件、标题和出现顺序。工程未承诺生产索引的更新或删除。 | 外部消费者若只追加，改标题或删主题后旧单元可能残留；这不是现有工具已经发生的错误。 | 定义按受众与版本分隔的新快照全集写入、成功后切换及旧快照回收；失败保持当前快照；不开发数据库插件。 |

现有去重只覆盖同模块同受众、去空白后完全相同的正文；相似标题只报告候选。公开样本未证明严重的近义重复问题，0.8 可报告单元数及重复候选，不先做语义去重。业务单元默认文档级追溯符合受众隔离；要追到事实须保留关系清单及基础发布正文，单独复制检索 Markdown 不具备完整证据链。

## 有意义的验收

1. 从许可明确的公开源码生成一个含权限条件、失败和未知的模块，检查**最终生成单元**是否独立提供足够证据；不能只测手写检索单元。
2. 对同一固定语料分别运行词法基线和一个实际运行的外部 FTS、向量或混合结果输入，检查有限 `top-k` 下必要条件、例外、未知、出处与受众。记录实现/模型、索引字段与配置、语料摘要和原始排名；手写排名仅验证导入格式，lexical-v1 不冒称真实 FTS。分别报告结果，不以小题集满分声称最终问答已验证。
3. 检查根级术语表缺口报告与原文位置、泛标题上下文及跨节锚点可达。
4. 用连续两份清单模拟标题变更、主题删除和受众迁移，验证导入示例的新快照不包含旧 ID，切换失败时当前快照仍完整。

通用语义去重、全面问法生成、生产向量数据库插件、自动增量重建及大规模模型比较不属于本次最小修复。交付顺序见[0.8.0 发布规划](0.8.0-implementation-plan.md)。
