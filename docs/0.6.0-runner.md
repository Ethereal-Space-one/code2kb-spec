# 0.6 本地接续执行器

Code2KB Spec 0.6 增加**可选**的本地运行账本。账本帮助长任务从文件和 Git 恢复进度；知识事实、批准依据和发布快照仍以知识项目中的正式文件为准。工程升级不改变知识文件格式，旧项目无需创建账本，也无需重新发布。

## 开始一次运行

知识项目须是独立、已有提交的 Git 仓库。先复制 [`文档仓库.gitignore`](../templates/文档仓库.gitignore) 中的 `.code2kb/` 忽略规则。运行状态只留在本机，不进入发布物或 Git 提交。

```bash
code2kb run-create --project-root /path/to/knowledge-project \
  --run-id run-2026-01 --all-modules --batch-size 5 --release-id example-v2
code2kb run-next --project-root /path/to/knowledge-project --run-id run-2026-01
code2kb host-next --host claude-code --project-root /path/to/knowledge-project --run-id run-2026-01
code2kb host-next --host codex --project-root /path/to/knowledge-project --run-id run-2026-01
```

`--all-modules` 使用功能大纲的模块顺序；也可多次给 `--module-id` 指定本次范围。创建结果报告入口总数、未归类数和待核查数，不会将后两者自动判为已覆盖。仅在确有可定位的业务材料时使用 `--business-intent`。要把检索评测纳入发布门禁，创建时传 `--retrieval-suite /path/to/suite.json`；套件摘要固定在账本中。

任务种类依次为盘点、模块 writer、可选业务意图、只读 reviewer、结论确认、候选准备、批次检查点、逐包批准、发布输入 Git 提交、发布与审计。确定性任务可用 `run-execute`；writer、reviewer、批准、Git 提交和发布必须由执行者完成相应实际工作，再用 `run-complete` 记录已经核实的结果。`run-complete` 的备注只保存摘要，不是批准凭据。

```bash
code2kb run-execute --project-root /path/to/knowledge-project --run-id run-2026-01 --task-id inventory
code2kb run-begin --project-root /path/to/knowledge-project --run-id run-2026-01 --task-id example.module:writer
# 按任务契约读取固定提交、编写模块文件，并核对证据与未知边界。
code2kb run-complete --project-root /path/to/knowledge-project --run-id run-2026-01 \
  --task-id example.module:writer --actor analyst --note '已核对入口、事实、失败路径和边界'
```

准备候选的自动执行会尝试从正文提取检索元数据；证据不足时任务失败，执行者应补齐正文或显式运行旧 `prepare` 命令，再重试当前任务。`confirm-claims` 只**记录**已做的语义复核，工具不会代替 reviewer 判断结论。批准步骤须先通过独立的 `approve` 或有效预授权 `policy-review`；账本和 Host 均不能自行授予批准。发布仍须取得本次发布授权。启用检索套件时，发布命令须显式包含 `--with-retrieval --retrieval-suite`，随后核对检索和关系审计。

## 状态、恢复与取消

账本位于 `.code2kb/runs/<run_id>/run.json`，采用原子替换。项目锁位于 `.code2kb/project.lock`；同一台 Unix 主机上的受支持修改命令共用锁。`run-execute` 在整个确定性命令期间持锁，独立 `prepare`、批准、发布和检索构建也会争用该锁。外部编辑器和其他工具不受这把锁约束，因此每项任务完成时还会检查文件差异。账本至少区分待执行、执行中、待复核、阻断、失败、完成和取消。

中断后先检查当前任务，再恢复未完成文件事务：

```bash
code2kb run-status --project-root /path/to/knowledge-project --run-id run-2026-01
code2kb recover --project-root /path/to/knowledge-project
code2kb run-resume --project-root /path/to/knowledge-project --run-id run-2026-01
```

`recover` 对治理半写回滚到前像；对发布安装根据旧指针、关键文件摘要和发布审计决定保留新版或恢复旧版。文件遭到事务外修改时阻断并保留现场，不猜测覆盖。`run-resume` 根据配置、规格、关系、Git 和已发布文件判断能否接续；待人工复核或授权的任务不会自动通过。取消用 `run-cancel`，不会删除已产生的文件。账本保留由项目所有者自行管理；删除账本前应确认没有未完成事务，且保留需要追溯的执行记录。

## 文件与权限边界

任务契约列出 project-relative `allowed_write_set`。writer 只允许当前模块、功能大纲和该模块运行证据；reviewer 与盘点任务不允许写入；治理命令只允许当前模块；发布只允许 `发布/`。执行器比较 Git 跟踪文件及未忽略文件的前后摘要，越界变化会阻断任务并保留差异。此检查发生在写入之后；它不能替代 Host 的目录权限隔离，也不能观察项目外的副作用。源码仓库只读取固定提交，不由执行器写入。

Git 提交检查点核对提交前后的路径、干净工作区和已批准输入；不会自动 `git add .` 或推送。跨模块影响只根据明确登记的事实引用精准传播。没有关系映射或依赖无法证明时，运行账本保守地要求相关模块复核，不能把“未发现依赖”说成“无影响”。

## 命令副作用与兼容

| 命令 | 项目内主要写入 | 约束 |
| --- | --- | --- |
| `check`、`impact`、`audit-release`、`retrieval-audit`、`relation-audit`、`retrieval-query` | 无 | 读取文件并校验；不代表自然语言正确 |
| `confirm-claims`、`prepare`、`approve`、`policy-review` | 当前模块正文、规格或清单 | 项目锁与治理事务；半写需先 `recover` |
| `publish` | 暂存目录、`发布/` 双版、清单与指针 | 持久发布事务；明确发布授权；可选 staging 内检索评测 |
| `retrieval-build`、独立 `retrieval-evaluate` | 已发布检索目录、评测报告、检索清单或就绪指针 | 与 runner 共用锁；独立旧命令仍可能改现有发布物，不应当作只读检查 |
| `run-create`、`run-begin`、`run-complete`、`run-resume`、`run-cancel` | `.code2kb/` 账本；`run-execute` 还会执行对应治理写入 | 账本不属于发布输入 |

原有 CLI 默认输出保持兼容。显式 `--output json` 返回 `response_schema_version`、`command`、`status`、`error_code`、`result` 和 `diagnostics`；成功与失败都只在 stdout 给一份机器响应，诊断也写到 stderr。此模式便于 Host 编排；默认知识项目完全不启用它时，发布目录和知识文件结构保持原样。

Claude Code 与 Codex 适配层只渲染同一任务契约，分别见 [`hosts/claude-code/README.md`](../hosts/claude-code/README.md) 和 [`hosts/codex/README.md`](../hosts/codex/README.md)。适配层不保存第二套状态，也不私存批准。这里的 Codex 适配指 CLI 任务渲染与接续契约；Codex 工具权限仍需使用者按运行环境配置。
