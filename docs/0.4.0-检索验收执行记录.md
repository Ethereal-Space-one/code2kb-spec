# 0.4.0 检索验收执行记录

状态：**开发集与保留集证据召回已测，候选冻结和 PR CI 尚未完成**。本记录对应[验收计划](0.4.0-检索验收与0.5.0启动计划.md)。

## 已完成

1. 选定独立公开样本 Starlette，固定提交、上游 BSD-3-Clause 许可、证据路径和文件身份。五个单元由公开材料重写，未使用私有知识库。证据与逐题审核见[样本目录](../conformance/retrieval/starlette/README.md)。
2. 建立三个开发题、三个保留题，按具体问答场景分组；两组仍共享部分上游文档与相邻主题，不能称为严格主题隔离。六题内容由用户指定的独立 AI 二轮复核，未进行人工审核。
3. 接通只读 `retrieval-query`：从通过基础与检索双审计的当前发布物返回候选证据、正文出处和受众，并标记 `answerability: not_assessed`。功能联动在确定性发布夹具中验证，不能替代真实语义质量验收。
4. 根据实际“FTS 召回证据 → 模型组织答案”链路，把曾加入的检索器 `answer|abstain` 决策口径撤回。0.4.0 保持 0.1 证据检索协议；账号锁定题要求召回认证错误单元及其“未给出锁定多久”边界，不要求检索器自行拒答。这是对验收对象的纠正，不表示机器人最终回答已经通过测试。

固定来源：`starlette@61123a5c76ebb9d5786758008945c4fbbb380bf6`。完整结果、语料摘要、套件和评测器摘要见[开发集基线](../conformance/retrieval/starlette/development-baseline.json)与[保留集首次运行](../conformance/retrieval/starlette/holdout-baseline.json)。两组题共享部分来源与相邻主题，不构成严格独立的总体质量估计。
