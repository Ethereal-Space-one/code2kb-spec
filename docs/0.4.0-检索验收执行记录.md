# 0.4.0 检索验收执行记录

状态：**开发集基线已测，候选尚未通过**。本记录对应[验收计划](0.4.0-检索验收与0.5.0启动计划.md)。

## 已完成

1. 选定独立公开样本 Starlette，固定提交、上游 BSD-3-Clause 许可、证据路径和文件身份。五个单元由公开材料重写，未使用私有知识库。证据与逐题审核见[样本目录](../conformance/retrieval/starlette/README.md)。
2. 增加 0.2 问题集与外部结果协议：显式 `answer|abstain` 决策，不可回答题不指定支持答案的单元；旧 0.1 继续可用。报告把有答案题的召回和不可回答题的决策分开统计。
3. 建立三个开发题、三个保留题，按具体问答场景分组；两组仍共享部分上游文档与相邻主题，不能称为严格主题隔离。开发题分别检查 HTTP 默认权限结果、调试模式错误响应、账号锁定未知。保留题尚未运行，也未用于调整排序或规则。
4. 定向测试覆盖拒答题的正确与错误决策、格式错误、CLI 评测和审计联动，以及公开样本校验。
5. 本轮最终代码的全量本地回归通过 134 项，检索定向通过 15 项；公开内容检查与 Markdown 本地链接检查通过。PR 合入前仍须按计划核对 CI。
6. 接通只读 `retrieval-query`：从通过基础与检索双审计的当前发布物返回候选证据、正文出处和受众；明确标记 `answerability: not_assessed`。功能联动在确定性发布夹具中验证，不能替代下面的真实语义质量验收。

## 开发集基线

固定来源：`starlette@61123a5c76ebb9d5786758008945c4fbbb380bf6`；当前语料 `views` 摘要 `a637c69ddede070ef07a4ed369d061fa657ab87fa44437f358431afdd69a1861`。完整结果和套件、评测器摘要见[开发集基线](../conformance/retrieval/starlette/development-baseline.json)。六题已按用户要求由独立 AI 二轮复核，未进行人工审核；决策策略和普通召回阈值仍未冻结。

| 指标 | `lexical-v1` |
| --- | ---: |
| 开发题通过 | 2/3 |
| 有答案题 module recall@2 / unit recall@2 | 1.0 / 1.0 |
| 有答案题 MRR | 1.0 |
| 不可回答题正确拒答 | 0/1 |
| 受众泄漏 / 禁止断言命中 | 0 / 0 |

失败题 `unknown-account-lock` 召回了认证错误响应单元，但该单元只说明可自定义错误响应，不能支持锁定次数或时长。内置基线把“有文字命中”当作 `answer`，因此本轮**不能宣称检索就绪**。不降低金标准，也不把“文档说没有规则”视作已经验证机器人拒答。

按用户要求，本轮停止围绕该小题集调参。`retrieval-query` 解决的是“从受控发布物取回可追溯候选证据”这一功能链路；可答性与生成回答质量仍属后续独立问题，不把功能联动测试当作语义质量分数。

## 尚需完成的验收动作

- 六题内容已由用户指定的独立 AI 复核并署名记录；证据或题意变动时须重新独立核对。
- 在决策策略和普通召回阈值事先固定后，只运行一次独立保留集。若使用保留题调参，需要废弃该组并重新选题。
- 无答案误答仍是硬阻断；须设计有证据的可答性判定或提交具有显式拒答决策的外部检索结果，再对同一题复测。不能仅通过让 lexical 对特定问法返回空来修饰结果。
- 候选内容冻结后核对公开内容与链接、完成 CI；0.4.0 通过后再启动 0.5.0 最小事实关系契约。

本记录不把检索单元中的短语覆盖解释为最终生成回答的质量。线上问答需要单独的回答评测。
