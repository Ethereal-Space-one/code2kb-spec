# Code2KB Spec 0.8.0｜检索完整性与源码升级预览

0.8.0 改进从代码生成的知识在检索索引中的完整性，并帮助维护者定位固定源码升级后可能失效的知识。它仍以人工或预授权审核后的知识正文为发布来源。

- 可选检索单元继承文件前言，并在识别到约定的条件或未知标题时保留整篇正文；同模块的泛标题跨文件聚合。覆盖报告列出未入检索版的术语表，以及因限定关系不明而整篇保留、需复核的来源。
- `preview-upgrade --all-modules` 对比旧、新固定 Git 提交，报告路径与片段变化、可追踪的事实/主题/检索单元、候选重定位和未归属路径。结果只用于制定复核范围，不自动修改知识。
- 外部 FTS/向量索引的导入契约要求先写完并核对新快照，再切换指针。失败时旧快照仍可用；参考实现只提供内存模拟。
- 许可明确的 PetClinic 公开样本用受控第二提交演练一条查询分支变化，通过实际关系发布与全项目预览命令定位影响，并记录同一语料、问题和 `top_k=1` 下的 lexical-v1 与 SQLite FTS5 原始排名。该小样本不代表线上运行、最终模型回答或多语言检索质量。

工程版本从 0.7.0 升至 0.8.0；文件协议仍默认 `c2kb-file/1`，并继续兼容读取旧 `0.8.3` 项目。已有知识项目不必迁移或重新发布基础双版。若要使用新检索聚合规则，应从已审核知识生成新的检索扩展或新发布，按快照导入契约更新外部索引。已发布目录与清单不就地修改。

限制：工具无法从源码自动确认业务政策、线上行为或未建立的调用关系；全项目预览的候选与“未发现”结果不可当作事实已验证。
