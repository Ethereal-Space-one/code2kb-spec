## 一个真实业务链的人工核对

- 前端 `src/app/owners/owner.service.ts:36` 使用 `environment.REST_API_URL + 'owners'` 构造地址，`:48` 发出查询，`:77-84` 在有姓氏时添加查询参数。环境文件 `src/environments/environment.ts:26` 给出基础地址。这些是固定源码行为；当前词法扫描没有把变量拼接解析为完整路由。
- 后端 `src/main/resources/openapi.yml:65-102` 定义 `/owners` 的 `get` 操作及可选 `lastName` 参数；`src/main/java/org/springframework/samples/petclinic/rest/controller/v1/OwnerRestControllerV1.java:53` 声明 `/api` 基础映射，`:78-89` 实现按 `lastName` 分支查找并在空结果时返回 `NOT_FOUND`。接口路径在 OpenAPI 文件和控制器间分布；当前 Adapter 对 YAML 仅做 L1 盘点，对 Java 只提出类级 `/api` 路由候选。
- 上述锚点支持人工编写“可按姓氏筛选主人；无匹配时此控制器返回未找到”的**源码限定**知识。运行环境实际 URL、代理配置、权限结果和线上返回仍待独立证据。当前 Adapter 输出不足以自动给出该事实或可信的前后端调用边。

## 对 0.7 冻结门槛的影响

合成夹具已证明“候选→人工复核事实→双版正文→检索单元”管道能够运行；本样本证明当前参考 Adapter 对真实的变量拼接和 OpenAPI 契约没有足够结构化提取。要宣称独立混合语言样本闭环通过，须先为这一类输入提供保守的结构化候选，或明确由人工锚点完成映射，并将整个样本的可复核事实、双版发布和检索结果纳入可重复验收。仅凭文件数和词法候选数不得放行 0.7。

复现时检出上表两个提交，分别调用 `validation.adapters.platform.scan(repository_id, {"path": 本地检出路径, "commit": 固定提交}, adapter_name="builtin-mixed")`。公开 CI 不依赖在线克隆，避免网络变化使本仓回归不稳定。
