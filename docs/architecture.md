# 架构说明

Code2KB Spec 分成三个层次：规范、参考实现和 Agent 工具。

```text
固定源码提交 ──证据锚点──▶ 知识项目
                               │
业务材料 ──脱敏证据────────────┤
                               ▼
                     人工审核或策略审核
                               ▼
                  业务版 / 研发版 / 版本清单
                               │ 显式启用
                               ▼
                    检索单元 / 离线评测 / 独立指针
```

| 组件 | 职责 |
| --- | --- |
| `SPEC.md`、`spec/` | 权威规范和稳定要求编号 |
| `validation/` | Python 参考实现 |
| `skills/` | AI 按任务加载的工作流 |
| `templates/` | 规范兼容的文件实例 |
| `adapters/` | 技术栈入口盘点提示与适配 |

事实变化通过 `impact` 传播到知识正文；`confirm-claims` 记录语义复核；`prepare` 绑定候选摘要；人工 `approve` 或策略 `policy-review` 形成独立审核溯源；`publish` 生成双版；`audit-release` 只依赖发布物即可校验快照。

0.4.0 的检索扩展只读取已审核的双版发布正文，确定性派生按主题切分的业务和研发单元。检索清单绑定基础 registry 摘要，问题集评测通过后才写当前检索指针。它不成为新的源码事实源，也不修改知识规范的双版清单。

参考实现不会修改源码仓库，也不会把结构检查提升为业务或线上证明。
