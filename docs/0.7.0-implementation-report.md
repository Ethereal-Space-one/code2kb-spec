# 0.7.0 实施与复核记录

> 本报告记录 0.7 候选源码的实际证据。工程版本、文件协议标识和使用方知识项目 `release_id` 分开管理；不引用任何私有使用方仓库。GitHub 标签、Release 与 Python 多版本 CI 的结果须在对应动作后另行登记，不能由本地单版本测试代替。

## 交付范围

- 新知识项目默认 `c2kb-file/1`；已公开的 `0.8.3` 知识项目继续按原校验强度检查、准备、发布和审计。旧发布物可由 0.7 参考实现审计，未知协议编号仍拒绝。
- 显式迁移提供完全无写的预演与摘要绑定执行；活跃运行、未完成事务、已审核包和脏工作区阻止迁移。执行只原子替换工作配置中的协议编号，不修改旧发布物或审核记录。
- 内置 `builtin-mixed` 和 `universal-l1` 适配器提供固定提交快照、候选身份、能力边界、源码锚点与保守跨语言线索。旧 `analyze-candidates` 默认格式和 JSON 响应外壳继续兼容。词法候选不会自动成为正式事实。
- 范围扫描在文件上限与词法分析前生效；关系候选的两个证据锚点必须对应其两端候选。

## 关键验收

| 检查 | 证据与边界 |
| --- | --- |
| 旧版连续链路 | 冻结的 0.6.0 发布物可审计；同一项目完成旧发布→显式迁移→新发布→审计；损坏发布物或未知编号被拒绝。 |

| 受众与公开边界 | 业务版继续禁止内部技术细节；公开内容扫描覆盖第三方源码夹具，未包含使用方知识项目。 |

## 保留的能力边界

参考 Adapter 的 TypeScript/Java 逐行匹配仍是 L1 词法候选；UniApp 标准页面清单具有限定的 L2 能力。真实项目的变量拼接、OpenAPI 契约与 Java 实现需要人工证据核对，跨仓库部署配对不能由同名或同路径断言。辅助语言只有文件级能力；检索单元验证出处和内容投影，不代表已评测模型生成的最终答案。
