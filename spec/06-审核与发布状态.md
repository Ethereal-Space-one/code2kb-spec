# 审核与发布状态

## 状态

```text
draft --approve--> reviewed
draft --policy-review--> policy_reviewed
reviewed | policy_reviewed --publish--> released snapshot
```

`prepare` 生成候选摘要并把旧审核戳恢复为 `draft`。正文、规格、证据、主题、未知边界或发布文件变化后必须重新准备。

## 人工审核

- **C2KB-REVIEW-001**：人工审核必须记录实际审核人、日期和授权边界原文。
- **C2KB-REVIEW-002**：工具执行、AI 自检和模板文字禁止冒充人工批准。

## 策略审核

- **C2KB-REVIEW-003**：策略必须由项目配置固定指向，并在审核前与 Git HEAD 一致。
- **C2KB-REVIEW-004**：审核记录必须绑定候选摘要、模块、固定源码提交、策略 ID、风险等级和检查结果。
- **C2KB-REVIEW-005**：策略过期、检查缺失、摘要不符、风险超限、阻断发现或人工门禁命中时必须拒绝策略审核。
- **C2KB-REVIEW-006**：策略审核可以验证记录和内置门禁，禁止声称已验证外部报告的自然语言真实性。

## 发布

- **C2KB-RELEASE-001**：发布前，候选正文、规格、清单、证据、策略和审核记录必须与当前 Git HEAD 一致。
- **C2KB-RELEASE-002**：版本清单必须记录规范版本、清单结构版本、内容版本、文档提交、生成器、审核溯源、双版路径和逐文件 SHA-256。
- **C2KB-RELEASE-003**：当前版本 JSON 是机器读取的唯一指针，并必须与版本清单摘要及双版路径一致。
- **C2KB-RELEASE-004**：发布失败必须保持或恢复原发布快照。
- **C2KB-RELEASE-005**：发布后必须执行纯产物审计；摘要、路径、文件集合或审核溯源不一致时审计失败。
