# 规范说明

## 约束词

本文使用以下约束词：

- **必须**：满足规范不可缺少的要求。
- **禁止**：任何兼容实现都不能执行的行为。
- **应该**：通常应满足；偏离时应记录理由和边界。
- **不应该**：通常应避免；采用时应记录理由和边界。
- **可以**：可选能力。

## 基线要求

- **C2KB-BASE-001**：新知识项目的 `standard_version` 必须为 `c2kb-file/1`；已有 `0.8.3` 项目保持兼容，不要求为了工程升级改写历史发布物。
- **C2KB-BASE-002**：工程发行版本、知识规范版本和项目 `release_id` 必须分别记录，禁止互相推定。
- **C2KB-BASE-003**：源码事实必须绑定仓库 ID、固定 Git 提交和仓库相对路径；禁止以可变分支或未提交工作区代替固定提交。
- **C2KB-BASE-004**：工具检查只能声明其实际验证的结构和摘要，禁止把机械检查描述为业务语义、线上行为或现实身份认证。
- **C2KB-BASE-005**：规范扩展不得放宽本规范的失败封闭原则；缺少必填证据或摘要不一致时必须拒绝审核或发布。

## 适用范围

本规范适用于从一个或多个代码仓库提取 Markdown 知识项目，并生成面向业务和研发的隔离发布物。机器人、向量数据库、模型供应商、部署系统和源码托管平台不属于规范的一部分。
