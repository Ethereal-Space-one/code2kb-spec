# 知识项目结构

## 必需结构

```text
知识项目/
├── 知识库配置.json
├── 知识源/
│   ├── 功能大纲.md
│   └── <业务域>/<模块>/
├── 运行证据/                 # 可选
├── 自动审核策略/             # 启用策略审核时必需
├── 自动审核记录/             # 使用策略审核时必需
├── 自动审核报告/             # 新策略审核使用 external.* 检查时必需
└── 发布/                     # 发布后生成
    ├── 业务版/
    ├── 研发版/
    ├── 版本清单/
    ├── 当前版本.json
    └── 当前版本.md
```

## 要求

- **C2KB-PROJECT-001**：知识项目必须使用独立 Git 历史管理配置、知识源、审核输入和发布快照。
- **C2KB-PROJECT-002**：`知识库配置.json` 和 `知识源/` 必须位于项目内，且禁止通过符号链接越出项目。
- **C2KB-PROJECT-003**：功能大纲必须逐项登记约定范围内的模块、入口、受众、范围和状态。
- **C2KB-PROJECT-004**：每个模块必须使用稳定且唯一的 `module_id`；目录名称可以中文化，但不得承担唯一身份作用。
- **C2KB-PROJECT-005**：发布目录必须使用固定的 `发布/业务版` 与 `发布/研发版`，两者禁止嵌套或相交。
- **C2KB-PROJECT-006**：旧发布快照必须由 Git 提交或标签恢复；Publisher 禁止覆盖未提交的当前发布目录。
