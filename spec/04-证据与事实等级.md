# 证据、事实与业务意图

## 事实等级

| 等级 | 含义 |
| --- | --- |
| `CODE_VERIFIED` | 固定源码提交直接证明 |
| `RUN_VERIFIED` | 限定环境的运行或部署证据证明 |
| `BUSINESS_CONFIRMED` | 明确业务确认材料证明 |
| `INFERRED` | 从证据推导但未直接验证 |
| `UNKNOWN` | 证据不足 |

## 要求

- **C2KB-EVIDENCE-001**：每条事实必须是带条件和边界的单一结论，并使用稳定 `FACT-*` 或 `F-*` ID。
- **C2KB-EVIDENCE-002**：源码锚点必须采用 `仓库ID:仓库相对路径:行号`，并能在固定提交中解析。
- **C2KB-EVIDENCE-003**：`INFERRED` 和 `UNKNOWN` 禁止改写成已发生的线上事实或已确认业务政策。
- **C2KB-EVIDENCE-004**：运行、业务和部署证据必须分别标记，且只能证明其记录的模块、事实、环境和有效期。
- **C2KB-EVIDENCE-005**：业务证据必须保存来源标题、定位、原始材料摘要和脱敏摘录；原始敏感材料不应该复制进知识项目。
- **C2KB-EVIDENCE-006**：进入业务正文的业务意图必须同时关联有效业务证据和至少一个当前模块行为事实。
- **C2KB-EVIDENCE-007**：`DOCUMENTED` 或 `BUSINESS_CONFIRMED` 意图可以进入机器人知识库；`INFERRED` 和 `UNKNOWN` 意图必须保持“仅内部”。
- **C2KB-EVIDENCE-008**：业务意图正文、规格 INT 表、业务证据 `intent_ids` 和事实影响文件必须双向一致。
- **C2KB-EVIDENCE-009**：过期证据禁止支持当前发布候选。
