# 发布维护

`prepare` 后、审批前按模块选择审核方式：人已明确批准时用 `approve` 记录实际审核人、日期和边界原话；项目已有有效预授权策略、本次记录且未命中人工门禁时用 `policy-review`。策略不适用时保持草稿交人工审阅；AI 自检或 `check` 通过都不是批准。完成所选审核后再发布。覆盖当前快照前，先将旧 `发布/` 完整提交到 Git。兼容的两个协议标识均使用双版、registry 2.0 和当前指针；只有显式 `--with-retrieval --retrieval-suite` 才把检索扩展随基础发布一起纳入门禁。

发布后先执行 `audit-release`；启用检索扩展时再执行 `retrieval-audit`。失败时恢复旧快照。不要通过直接编辑发布目录修复问答，回到知识源修改、重审并用新内容版本发布。详见 [发布与维护](../references/发布与维护.md)。
