# 高影响语义闭环

在权限、归属、金额、名额、指标或状态会改变回答时使用本参考。目标是留下可审计的生产、条件、消费与边界关系，让后续 agent 能沿同一条证据链复核。

## 字段与业务术语

从入口追到核心方法后，列出会改变业务含义的字段级副作用。至少核对：直接 setter、方法引用、链式更新、ORM/XML 列名、批量更新、消息监听器、回调和定时任务。相近概念分别定义，例如“订单所属渠道”和“处理任务负责人”不能因都表示归属关系而合并。

闭环应回答：谁生产或写入、满足什么条件、与其他写入的先后关系、哪些模块读取或据此显示/限制操作、固定源码能证明什么、运行顺序或配置映射还有什么未知。多个写入来源不能归纳成单一来源；缓存回退、默认分支和未知枚举映射要保留真实条件。

只登记会改变答案或风险判断的字段与术语，不穷举普通 DTO 字段。每一行关联现有 fact_id，事实影响文件继续由 impact 与 confirm-claims 管理。“类型”使用字段、业务术语、状态、权限、归属、金额、名额或指标；权限、归属、金额、名额、指标和状态属于必须覆盖的高影响范围。

## 动态配置

配置调用的命名空间、键名、使用方式和缺失行为属于静态证据。实际运行值、发布环境覆盖与缓存新鲜度需要另外的运行或配置证据。源码已经出现键名时必须记录；取值未知写 `UNKNOWN（缺少运行配置证据）`，不能把键名一起省略。

若键通过常量或包装函数间接传入，沿定义追到能证明的最远位置；仍无法确定时登记 UNKNOWN 事实与缺口，不编造键。

## 三类语义自测

- 字段副作用：从入口和核心方法反查，高影响写入路径、条件、顺序及消费方是否完整。
- 配置键：动态配置是否保留命名空间、键名、使用与缺失行为，并把运行取值单独定级。
- 正文一致性：同一场景在规格、业务正文和研发正文中的条件、聚合方式、固定值、失败结果和未知边界是否一致。

工具只能验证表格完整、事实与源码锚点存在、三类自测已记录为通过，以及内容变化后旧审核失效。工具不能理解自然语言，也不能证明源码扫描穷尽；复核者须实际读证据和正文后再标通过。

## 启用与兼容

项目在 `知识库配置.json` 中显式启用：

```json
"semantic_quality": {
  "enabled": true,
  "module_ids": ["app.example.module"]
}
```

`module_ids` 可列明确模块，或单独使用 `"*"`。未配置或 `enabled: false` 时不强制语义质量表。启用模块必须使用结构化规格模板中的三个章节；`check`、`prepare`、策略审核和 `publish` 共用同一门槛。
