# 业务意图与材料证据（文件协议兼容：c2kb-file/1 与 0.8.3）

业务意图用于回答“为什么有这条规则、它解决什么问题、会产生什么业务影响”。它不是从代码自由推断出的动机。进入机器人知识库必须形成完整链路：

```text
业务证据 → INT 意图主张 → 当前模块行为事实 → 业务意图正文
```

## 两类状态

- `BUSINESS_CONFIRMED`：由明确人工确认支持，业务证据使用 `source_type: human`。
- `DOCUMENTED`：由正式业务材料支持，业务证据使用 `source_type: document`。
- `INFERRED`、`UNKNOWN`：只留在规格和待确认事项，发布范围为“仅内部”，不得进入 `业务意图.md`。

规格表使用稳定 `INT-001` 一类 ID。机器人范围的每行同时引用至少一个业务 EVID 与一个当前模块事实；对应事实的影响文件包含 `业务意图.md`。正文 `## 关键规则的原因` 下的三级标题与机器人范围意图按顺序一一对应。

## 原始材料处理

原始制度、会议纪要、聊天记录、工单和客户资料保留在原系统。生成项目只保存：

1. 脱敏摘录；
2. 材料名称与版本；
3. 可供授权人员回查的来源定位；
4. 原始材料的 SHA-256；
5. 本证据覆盖的 intent_ids；
6. 适用范围、有效期与不能证明的事项。

不得保存原始凭据、手机号、客户资料或完整内部材料。`source_sha256` 对原始材料计算，不能用脱敏摘录的摘要替代。业务证据模板见 `templates/业务证据.md`。

人工确认另填 `confirmed_by`、`confirmed_at`、`confirmation_note`。确认备注写清场景和边界，不能只写“确认”。

## 自动审核门禁

`check`、`prepare`、`policy-review` 和 `publish` 都会复核意图结构和证据链。证据过期、来源信息不完整、证据未覆盖 INT、缺少行为事实、正文标题不一致或敏感扫描命中时拒绝。普通未确认意图留在内部，不阻塞同模块其它已确认知识发布。

`prepare --files` 可以明确排除 `业务意图.md`；发布清单会记录 `intent_included: false`。只有清单写为 `true` 且候选确实包含该文件时，意图才进入业务版和研发版。
