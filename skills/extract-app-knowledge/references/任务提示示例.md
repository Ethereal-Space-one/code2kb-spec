# 可复制任务提示（文件协议兼容：c2kb-file/1 与 0.8.3）

从 [使用指南](../../../docs/usage.md) 启动 Code2KB Spec 后，按当前节点选用一段；这些示例不替代项目范围、配置或人的批准。

**生成全范围大纲：**

> 读取项目配置中的全部固定提交和约定范围，盘点适用的页面/按钮、API、消息、定时及动态入口，逐项记录稳定入口 ID、模块归属、受众、范围和固定提交锚点；有页面适配器时逐项对账。主会话分类、去重、写 `知识源/功能大纲.md`，说明未归类与未覆盖的入口；完成自检后标 `inventory_status: complete` 并运行 `check`。此前不写模块文件，不修改源码仓库。

**提取一个模块：**

> 确认大纲 complete 且 `check` 通过，以〈模块 ID〉重追入口条件、前端/调用方动作、接口或消息、服务端分支、状态副作用、失败和反馈。写完整 `结构化规格.md`：稳定 fact/API/METHOD ID、请求响应和参数位置、接口调用匹配、核心方法分支、固定源码锚点、未知项；必要时写 `待确认事项.md`。独立复核关键结论，静态事实、推断、运行证据与未知分开。

**写知识并验收：**

> 从已核查规格生成中文业务正文，再生成技术导航及有内容的接口/方法正文；逐项对账事实、接口与方法 ID。用正常、失败、未知、越权问题自测并按实际行数报告。运行 `check` 和 `impact`，对受影响文件做语义复核后运行 `confirm-claims`、`prepare`。人工模式在人明确批准后才按原话执行 `approve`；策略模式只使用项目配置中预先提交的策略和本次审核记录执行 `policy-review`，命中人工门禁时保持草稿。AI 自检或其他 AI 建议本身不是人工批准或策略审核。
